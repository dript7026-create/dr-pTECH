# drIpTECH Workspace Push Protocol

This document defines the minimum release gate for any full-workspace push from the drIpTECH repository.

## Goals

- protect business continuity and financing posture
- preserve ethical, legal, and market-facing publication discipline
- keep local launch-key workflows versioned without storing live secrets
- make milestone pushes auditable and reproducible

## Full Workspace Push Gate

1. Run `powershell -File scripts/prepare_workspace_push.ps1` from the repository root.
2. Confirm the security scan passes for the full tracked view.
3. Run `powershell -File scripts/publication_scope_pass.ps1` or review the report generated by push prep at `.tmp/publication_scope_review.json`.
4. Review the generated filesystem signature at `.tmp/workspace_push_signature.json`.
5. Verify that only publication-safe files are staged for the final push and that excluded archive, review, or workstation-local artifacts remain out of scope.
6. Push manually after review. Unattended mirror pushes are out of policy for this repository.

## Launch Key Protocol

- `set_openai_key.ps1` and `set_recraft_key.ps1` are deliberate, versioned helpers.
- They are allowed to prompt for key material and populate the current or user environment.
- They are not allowed to store live keys in tracked files, CI configuration, generated logs, or manifests.
- When a workflow only needs model access for a local session, prefer non-persistent use.

## Security And Longevity Rules

- Keep lender, financing, budget, legal-incident, certification, and operator-state files outside the public mirror unless intentionally redacted.
- Keep market-sensitive strategy, unpublished partnership terms, and pricing posture out of unattended publication flows.
- Prefer changes that are reversible, reviewable, and attributable to a human operator.
- Disable or guard any script or workflow that can push to mirrors or remotes without an explicit manual acknowledgement.
- Treat the filesystem signature as release evidence, not as a substitute for review.

## Filesystem Signature

- `scripts/write_workspace_signature.ps1` produces the current governance-boundary signature for the repository.
- The signature covers the push-boundary policy, scanner, launch-key helpers, and push-prep scripts.
- The generated artifact is written to `.tmp/workspace_push_signature.json` and can be regenerated at any time from the same tree.

## Publication Scope Review

- `scripts/publication_scope_pass.ps1` classifies current worktree changes into `publish_now`, `review_required`, and `exclude_from_push_now` buckets.
- The generated report is written to `.tmp/publication_scope_review.json` and is intended to reduce accidental publication of local review bundles, archives, backup material, or unrelated project churn.
- Use `-StagePublishableSet` only when you want the script to stage the explicit publish-now subset; everything else remains manual by design.
